# 숙박비·관리자·패스 수정 검증 (2026-10-25)

- 날짜 미지정 일정도 조회 당일(일본 시간)의 숙소별 1박 공개 최저가를 사용한다. 숙박 기간의 가상 날짜로 가격을 조회하지 않는다.
- 숙박 합계는 확인한 1박 최저가 × 박 수. 객실 수나 인원수로 방 개수를 추정하지 않는다.
- 라쿠텐 조회 실패 시 Gemini 검색, 그 후 OpenAI Responses 웹 검색으로 보완한다. 설정된 모델을 그대로 사용한다.
- Gemini 보완 조회의 2숙소 제한을 제거했다. 라쿠텐 직접 조회의 기존 20숙소 상한은 유지한다.
- 웹 검색 결과에는 실제 검색 출처, 정확한 숙소 이름, 명시적인 JPY 1박 요금이 필요하다. 여러 박 합계·주차비·임의 환산 요금은 제외한다.
- 가장 저렴한 요금 한 개만 반영한다. 확인하지 못한 요금은 비워 둔다.
- 검색 캐시는 별도 SQLite에서 최대 24시간 유지하며 전날 조회 결과를 새 당일 요금으로 재사용하지 않는다.
- 생성된 일정의 가격은 같은 보조 SQLite의 별도 일정 요금 테이블에 보존한다. 일정을 나중에 열어도 조회 당일 가격이 바뀌지 않는다. 원본 MariaDB 관광지·회원·일정 테이블 스키마는 변경하지 않았다.
- 숙박비 작업의 기존 최대 2분 대기를 제거하고 취소 가능한 대기로 변경했다. 일정 실패·취소 시 하위 요금 작업도 중단한다.
- VM 비공개 application-docker.properties에 기존 관리자 및 환율 편집자 이메일 설정을 복원했다. 기존 파일은 같은 비공개 디렉터리에 백업했다. 기존 USER 토큰은 자동 승격하지 않으므로 로그아웃 후 재로그인이 필요하다.
- 일반 승차권만 사용하는 날의 중복 문구를 제거했다.
